# DeepSeekBridge

Windows 上的轻量基于 DeepSeek chat 的阅读助手，可在日常使用时可以作为快速的翻译以及查询工具。

通过配置好的鼠标按键或键盘快捷键调用。浏览器内可以选中文字或使用剪贴板，在当前浏览器中查询；其他应用中请先手动复制，再调用程序，程序会激活默认浏览器，优先复用当前 DeepSeek 对话完成查询。

不需要 API Key、浏览器扩展（使得在使用浏览器阅读本地文件时也可调用）或常驻服务。不向文字添加提示词，翻译或解释行为取决于你的 DeepSeek 对话设置。

## 版本与下载

当前版本为 **v1.1.18**，修正 Edge 选区复制判断及新建分屏后网址入口被误排除的问题。在 [Releases](https://github.com/J1nCw/DeepSeekBridge/releases/tag/v1.1.18) 下载 `DeepSeekBridge-v1.1.18-win-x64.zip`，完整解压后使用。更新时先退出程序，再覆盖原目录文件，保留 `logs` 文件夹，并保持 EXE 的名称和所在路径不变，以便原鼠标按键配置或 Windows 快捷方式继续使用。

## 配置与使用

首次配置：将程序完整解压到有写入权限的固定目录，在 Edge 或 Chrome 中登录 [DeepSeek](https://chat.deepseek.com/)，再选择下面任一调用方式：

- **鼠标按键**：在鼠标配置软件中，将一个按键设为启动 `DeepSeekBridge.exe`。具体功能名称取决于鼠标软件，通常为“启动程序”或“运行程序”；无需额外添加自动复制动作。
- **键盘快捷键**：为 `DeepSeekBridge.exe` 创建 Windows 快捷方式，并按下文设置快捷键，无需支持宏的鼠标。

**浏览器内：划词或准备好剪贴板 → 按配置好的鼠标按键或键盘快捷键。其他应用内：手动复制 → 按配置好的鼠标按键或键盘快捷键。**

> **调用后，请在 DSB 完成填入、发送和发送确认前暂停其他点击或键盘操作。** 浏览器来到前台后保持前台，不要切换窗口、标签页或分屏焦点。DSB 成功退出后即可继续操作，**不必等 DeepSeek 回答完毕**。详见下方“运行期间的操作注意事项”。

| 调用时所在界面 | 程序如何查询 |
|---|---|
| Edge / Chrome 普通网页或 PDF | 有选区时优先复制；没有选区时使用剪贴板。保留阅读页面，打开或复用 DeepSeek 分屏 |
| Edge / Chrome 独立新标签页 | 直接在当前标签页打开 DeepSeek，不新建分屏 |
| 已有 DeepSeek 页面或分屏 | 复用现有页面，保留分屏位置和宽度 |
| 其他应用或桌面（v1.1.16） | 仅读取剪贴板；激活默认浏览器，当前页面是 DeepSeek 时复用原对话，是独立空白标签页时在原标签页打开，否则新开 DeepSeek 页面；不识别原应用选区、不创建分屏 |

### 设置 Windows 键盘快捷键

以下名称以简体中文 Windows 为例。属性字段可能带有 `(K)` 等访问键标记，具体显示随系统版本而异。

1. 在解压后的文件夹中右键 `DeepSeekBridge.exe`，选择 **发送到 → 桌面(创建快捷方式)**。Windows 11 如未显示“发送到”，先选择 **显示更多选项**。程序本体仍留在原文件夹。
2. 在桌面上右键新生成的快捷方式图标，选择 **属性**；在打开的属性窗口中切换到 **快捷方式** 选项卡。桌面图标的名称可能带有“快捷方式”后缀，不必与某个固定名称一致。
3. 找到 **快捷键** 字段（常显示为 **快捷键(K):**），点击右侧通常显示“无”的输入框，按下例如 **Ctrl + Alt + D** 的组合，确认框内显示该组合后，点击 **应用**，再点击 **确定**。若与其他软件快捷键冲突，请换一个组合。
4. 回到要查询的页面或应用，准备好选区或剪贴板，再按下并及时松开设置好的组合键，即可调用程序，无需切回桌面。浏览器内可以划词；其他应用内仍须先手动复制。

注意：这里修改的是 **快捷方式（.lnk 文件）的属性**。直接打开 EXE 的属性不会出现用于设置组合键的“快捷方式”选项卡。

请保留该桌面快捷方式。若不想在桌面放图标，可以将它移到当前用户的开始菜单程序文件夹：按 **Win + R** 打开“运行”，在 **打开** 输入框中输入 `shell:programs`，点击 **确定**；将快捷方式放入打开的文件夹，再检查其快捷键设置。不要放进“启动”文件夹。

更新时保持 EXE 的名称和所在路径不变；若移动了程序，需更新快捷方式的“目标”或重新创建。取消快捷键时，在同一输入框按 Backspace 清除后应用即可。

菜单路径可参考微软的 [桌面快捷方式说明](https://support.microsoft.com/zh-cn/windows/experience/personalization/customize-the-desktop-icons-in-windows)。此方案利用 Windows 自带的 [快捷方式键盘快捷键机制](https://learn.microsoft.com/en-us/windows/win32/shell/links#shortcut-keyboard-shortcuts)，程序仍按需启动，不常驻。

### 在浏览器内调用

1. 在网页或 PDF 中选中文字；也可以不划词，直接使用提前复制好的文字。
2. 保持该浏览器在前台，按下并松开配置好的鼠标按键或键盘快捷键。
3. 程序使用当前 Edge 或 Chrome，不受系统默认浏览器影响。

已有分屏保留原布局；仅首次创建分屏时尝试将 DeepSeek 放在右侧，目标宽度约 18%，受浏览器最小宽度限制。

### 在其他应用内调用（v1.1.16）

1. 将 Windows 默认浏览器设为 **Chrome 或 Edge**，并在该浏览器中登录 DeepSeek。
2. 在当前应用中使用它自己的复制功能，将要查询的文字放入系统剪贴板。仅划词而未复制时不会读取该选区。
3. 按下并松开配置好的鼠标按键或键盘快捷键。程序读取剪贴板，再激活默认浏览器最靠前的窗口（最小化时先还原）。当前页面已确认是 DeepSeek 时，直接在原对话查询；如果是独立空白标签页，直接在这个标签页打开 DeepSeek；普通网页则沿用新开 DeepSeek 页面的流程。浏览器未启动时会先启动。

多窗口时，只检查默认浏览器中最靠前窗口的当前页面及可见分屏，不遍历后台标签页，也不按标题跳到另一个窗口。复用前核对真实 DeepSeek 网址；原对话正在回答或有草稿时，仍停止并提示，不另开页面绕过保护。

此入口不读取原应用选区、文本、控件树或终端输出，不向原应用发送 Ctrl+C 等复制按键，也不改写剪贴板。只保留判断当前是否为 Edge/Chrome 及核对窗口是否变化所需的窗口句柄、进程标识和进程名。Linux/WSL/SSH 终端请自行使用终端支持的复制方式；之后程序只读取 Windows 系统剪贴板。也可从桌面或文件管理器启动。

Chrome 和 Edge 的跨应用入口都不会创建分屏。复用空白标签页时会核对页面和原生地址栏，并在输入网址前再次确认；地址栏有未提交输入或页面状态不明确时停止提示，避免覆盖已有内容。

### 运行期间的操作注意事项

DSB 通过前台浏览器控件和键盘输入完成操作。调用后通常只需等待几秒；期间请不要点击其他应用、切换标签页、最小化浏览器，或在地址栏/输入框中输入。跨应用调用时，先等待程序将默认浏览器切到前台，再保持该窗口不变。

请区分两个阶段：

- **DSB 正在打开页面、填入文字、发送及核对发送结果**：保持浏览器前台并暂停其他操作。实用判断是看到本次消息进入对话、输入框清空后再稍等片刻，给程序留出确认时间。
- **DSB 已成功退出，DeepSeek 正在生成回答**：可以自由切换窗口或继续工作，无需等待回答结束。DSB 不负责持续监控回答内容。

程序检测到前台窗口改变时会停止并提示 `B02`，不会反复抢回前台后继续输入，以免干扰正在操作的其他应用。在同一个浏览器窗口内换标签页或乱点也可能改变目标或焦点，不一定表现为 `B02`，因此运行期间同样应避免。

如果不小心切走，先回到 DeepSeek 检查：**消息已经发送就不要再次调用；输入框留有文字时先核对并处理草稿；确认没有发送后再重新调用。** 尤其在刚触发发送、尚未完成确认时切换窗口，即使弹出停止提示，消息也可能已经发出。程序不会自动重发。

### 兼容范围与异常处理

- 新标签页识别覆盖 Edge/Chrome 的若干内置页面形式及 `about:blank`。**不保证兼容任意第三方新标签页扩展或自定义主页**；普通自定义主页按普通网页处理。
- 地址栏自动选中的网址不会作为查询内容。若出现 `N01`，请等新标签页加载稳定；地址栏有未提交输入时，先按 Esc 取消再调用。
- Edge 的网页/PDF 可访问性接口返回空选区时，也会尝试原生复制，避免误用旧剪贴板；地址栏内选中的网址仍不会复制。选区状态未知时，最多等待 1.5 秒，剪贴板未变化才使用已有文字。已确认存在选区但复制失败时仍停止并报错。
- 创建 Edge 分屏前记录原阅读页身份；分屏后重新取得控件时，只保护原页面及原阅读侧，不将新出现的右侧入口重新记为来源。已有分屏中的普通页面仍保留保护。
- Edge 查找 DeepSeek 或右侧分屏入口时，针对控件失效、暂时忙碌等已知错误最多读取 3 次，每次重试前等待 80 毫秒并重新取得控件。不会因此重试发送。异常日志包含具体 COM 错误码，不记录选中文字。
- 没有可用文字、一次超过 30,000 字符、窗口切换、DeepSeek 已有草稿或正在回答时，程序停止并提示。
- 每次调用最多发送一次。成功静默退出，异常弹窗；整次操作保留 10 秒超时保护。提示发送状态不明确时，请先检查对话，避免重复调用。
- 默认浏览器启动或激活失败时不会继续输入。日志仍保存在 EXE 旁的 `logs` 文件夹。

## 系统要求与兼容性

- Windows x64，.NET Framework 4.x（构建环境使用系统 v4.0.30319 编译器）。
- Edge / Chrome 需支持原生分屏，并开放对应的 Windows UI Automation 控件。
- 浏览器和程序以同等权限运行，通常均不需要管理员权限。
- 基于 Edge 152 和 Chrome 143 环境开发。实际可用性还受浏览器界面语言、版本、缩放和 DeepSeek 页面变化影响；内置名称适配以简体中文和英文为主。

基础分屏与发送流程已有用户实测；v1.1.7 的 Edge 多标签页首次新建分屏修复已通过本次用户实测，尚需扩大实机验证范围。不能保证适配所有版本。若已发送却出现“状态不明确”提示，请先查看对话，不要立即重复调用。

## 性能与本地记录

启动时不再固定等待 400 毫秒，仅在鼠标键或修饰键仍按住时短暂等待松开。程序仅在主动运行时工作，不开机启动、不常驻、不持续监听剪贴板。成功结束后不保留运行进程。DeepSeek 网页自身仍使用浏览器资源。

从 **v1.1.6** 起，记录统一保存在 **`DeepSeekBridge.exe` 所在文件夹的 `logs` 子目录**，不依赖 Codex，也不依赖鼠标软件设置的工作目录。例如解压后的结构为：

```text
DeepSeekBridge/
├─ DeepSeekBridge.exe
├─ README.md
└─ logs/                  # 首次正常运行时自动创建
   ├─ status.txt
   ├─ review-report.txt
   ├─ recent.txt
   └─ maintenance.txt
```

你把程序解压在哪里，运行记录就跟随保存在那里。请先完整解压再运行；目录不可写时会提示 `F01`，不会偷偷改存到其他位置。移动程序时一并移动 `logs` 可以保留运行历史和提醒计时。发布压缩包不附带开发者的运行日志。

| 文件 | 用途 |
|---|---|
| `status.txt` | 最近一次结果、阶段耗时、CPU 时间和峰值工作集 |
| `review-report.txt` | 最近 500 次运行的摘要，不含正文 |
| `recent.txt` | 最近一次发送尝试的指纹，用于 15 秒内防重复 |
| `maintenance.txt` | 每月检查提醒时间 |
| `trace.txt` | 仅使用 `--diagnostics` 时启用的本地诊断记录 |

从首次使用开始，每 30 天在下一次成功调用后提醒检查运行记录。提醒 20 秒后自动关闭，也可点击打开记录文件夹。没有后台定时任务，不自动上传记录。

旧版 v1.1.5 及更早版本使用 Windows 的 `%LOCALAPPDATA%\DeepSeekBridge`，那也不是 Codex 目录。新版不会自动读取或导入旧记录；如需继续保留旧历史，可在程序未运行时手动把旧目录中的记录文件复制到新 `logs` 目录，避免覆盖已有的新记录。

默认摘要不保存剪贴板正文、文献标题或网址。诊断模式可包含界面控件标签，请自行检查后再分享。不要把运行记录提交到公开仓库。

## 源码构建

```powershell
.\development\build.ps1
```

脚本先生成候选程序，运行离线自测，通过后替换根目录 `DeepSeekBridge.exe`。失败时保留现有 EXE。构建使用 Windows 自带 C# 编译器，无 NuGet 依赖。也可运行 `DeepSeekBridge.exe --self-test` 单独验证规则，不会访问浏览器或剪贴板。

v1.1.18 包含 162 项离线检查。新增测试先在旧逻辑下重现了右侧空网址/在线新标签页被误排除的问题，修复后通过，并检查已有页面保护及来源控件重建。实际 Edge 网页/PDF 的端到端流程仍未在本次验证；用户已在 v1.1.13 确认本机 Chrome 跨应用调用和前台激活可用。Edge 跨应用分支已作代码核对，尚未完成同等实机验证。离线检查与单机试用不代表适配所有应用和浏览器环境。

程序通过正常窗口与 UI Automation 接口工作，不启用远程调试端口。浏览器或 DeepSeek 改版后可能需要更新适配。
